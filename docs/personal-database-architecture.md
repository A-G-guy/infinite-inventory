# 数据库架构说明

## 目标

这个模组把玩家的物品管理从有限背包扩展为“数据库式仓储系统”，当前同时提供个人数据库与公共数据库两种存储域。

当前版本的核心目标如下：

- 每个玩家都有一个个人数据库实例，数据跟随玩家附件持久化。
- 每个存档只有一个公共数据库实例，所有玩家共享同一份内容。
- 数据库快捷物品只是入口，不承载真实存储内容。
- 玩家死亡后数据库内容不会掉落，也不会因为快捷物品丢失而丢库。
- 数据库页面采用全屏原版增强布局，左侧是贴边停靠的玩家原版背包列，右侧是数据库主工作区，并提供个人库/公共库切换。
- 顶部工具栏支持图标分类页签、名称搜索、高级搜索、排序、紧凑分页以及一键入库；这些视图设置按玩家、按库分别记忆。
- 公共数据库的内容改动会实时同步到所有当前正在查看公共库的玩家，但每个人看到的筛选、排序与分页保持各自独立。

## 领域划分

### `database`

负责数据库领域模型与序列化：

- `StoredItemDatabase`：通用数据库存储核心，负责条目表、数量统计与序列化。
- `PlayerDatabaseAttachment`：玩家级个人数据库仓储。
- `PublicDatabaseSavedData`：存档级公共数据库仓储。
- `DatabaseViewPreferencesAttachment`：玩家级视图偏好，记录上次所选库以及个人库/公共库各自的查询状态。
- `DatabaseScope`：数据库作用域枚举，区分 `PERSONAL` 与 `PUBLIC`。
- `StoredStackKey`：使用物品本体和组件作为唯一键。
- `StoredStackEntry`：记录数量、分类和最近修改序号。
- `DatabaseQuery` / `DatabaseViewState` / `DatabasePage`：查询与页面投影。

### `service`

`PersonalDatabaseService` 负责数据库打开、入库、提取、分页、排序、筛选以及公共库观察者同步，是服务层总入口。

### `menu`

`PersonalDatabaseMenu` 负责：

- 复制原版背包布局。
- 维护 2x2 crafting、盔甲、副手和主背包槽位。
- 维护当前作用域以及个人库/公共库各自的查询状态。
- 将数据库交互转换为服务层操作。
- 在服务端生成数据库页面快照并同步给客户端。

### `client`

`PersonalDatabaseScreen` 负责全屏界面表现：

- 左侧使用 `VanillaPlayerInventoryPaneProvider` 复用原版背包背景和洋娃娃渲染，并固定停靠在页面左列。
- 右侧使用原版风格面板承载数据库网格与统计区，网格从左上角起排布并按分辨率自适应容量。
- 顶部提供个人库/公共库切换按钮、带物品图标的分类页签、带搜索图标的搜索框、高级搜索按钮、排序下拉、分页控件和一键入库按钮。
- 排序下拉当前支持最近变更、名称、数量、模组命名空间和物品 ID，多数规则都会在主排序键相同后继续用稳定键兜底，避免刷新后顺序抖动。
- 高级搜索使用折叠面板呈现，支持 `显示名称 / 物品 ID / 拼音 / 模组命名空间 / 数量加权` 五个要素同时启用，并分别配置 `低 / 中 / 高 / 关闭` 权重。

### `network`

自定义 payload 用于客户端与服务端同步：

- `DatabaseSnapshotPayload`：服务端下发页面快照，以及个人库/公共库各自的已记忆查询。
- `DatabaseQueryPayload`：客户端提交库切换、分类、排序、搜索、高级搜索配置和分页查询。
- `DatabaseClickPayload`：数据库格子点击、Shift 快速提取以及拖拽物品入库。
- `DepositAllPayload`：当前所选库的一键入库。

## 持久化与死亡语义

个人数据库与视图偏好都通过 NeoForge `AttachmentType` 绑定到玩家实体，并启用 `copyOnDeath()`。

公共数据库使用 overworld `DimensionDataStorage` 中的 `SavedData` 持久化，因此一个存档只会存在一份公共数据库。

为了保证入口物品不影响真实数据：

- `LivingDropsEvent` 会移除数据库快捷物品的掉落。
- `PlayerEvent.Clone` 在死亡且未启用 `keepInventory` 时补回快捷物品。

这样可以确保数据库内容和入口物品都符合“死亡不掉落”的预期，同时个人库、公共库与入口物品彼此解耦。

## 同步语义

- 个人库修改后，只刷新当前玩家自己的数据库页面。
- 公共库修改后，会刷新所有当前正在查看公共库的玩家页面。
- 刷新时只会重算各自当前查询，因此不同玩家可以用不同排序、搜索和分页查看同一份公共内容。

## 当前兼容策略

当前左侧界面已完整支持原版背包区、盔甲、副手和洋娃娃。

第三方饰品栏兼容暂时通过 `PlayerInventoryPaneProvider` 预留扩展点，后续可以在不重写数据库主页面的前提下接入更多玩家面板提供者。

## 已知边界

当前版本有意保持以下边界：

- 非空搜索时结果固定按综合相关度优先：先比较精确、前缀、包含、模糊命中层级，再比较加权文本分和数量加权分，最后才落到手动排序与稳定键兜底。
- 搜索索引统一基于服务端固定 `zh_cn` 名称构建，同时补充 `物品 ID`、`模组命名空间`、拼音全拼与首字母索引，以保证单机和联机的中文检索一致。
- 分类页签为固定枚举，不支持玩家自定义标签。
- 右侧数据库区目前是自定义渲染，不是传统容器槽位。
- 公共数据库当前不做权限、审计或锁控制，冲突以服务端先处理成功的结果为准。
- 快捷物品默认通过创造栏获取，后续可以增加更多入口。

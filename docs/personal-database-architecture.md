# 数据库架构说明

## 目标

这个模组把玩家的物品管理从有限背包扩展为“数据库式仓储系统”，当前同时提供个人数据库与公共数据库两种存储域，并重点保证以下事情：

- 数据库真实内容不依赖入口物品。
- 玩家死亡、模组更新、依赖暂时缺失时，数据库内容都不会直接丢失。
- 个人库与公共库共用一套持久化、备份与恢复机制。
- 玩家的筛选、排序、分页与库切换偏好依旧按玩家记忆，且不互相影响。

## 领域划分

### `database`

负责数据库领域模型、统一存储和恢复能力：

- `StoredItemDatabase`：通用数据库存储核心，负责条目表、未解析条目保留、数量统计与版本化序列化。
- `DatabaseStorageSavedData`：唯一真实数据库载体，挂在 overworld `SavedData`，同时持有公共库、按玩家 UUID 划分的个人库，以及旧附件迁移状态。
- `PlayerDatabaseAttachment`：旧个人数据库附件，现阶段只保留为迁移源，不再作为真实数据库事实来源。
- `DatabaseViewPreferencesAttachment`：玩家级视图偏好，记录上次所选库、个人库/公共库各自的查询状态，以及可选加强项开关。
- `UnresolvedStoredEntry`：保存暂时无法解析的原始物品 NBT，避免依赖缺失时直接丢条目。
- `LegacyMigrationState`：记录旧个人附件迁移是否已导入、已清理或因现有统一存储而跳过。
- `StoredStackKey` / `StoredStackEntry`：已解析条目的唯一键和数量记录，其中条目同时保存“首次入库序号”和“最近修改序号”。
- `DatabaseQuery` / `DatabaseViewState` / `DatabasePage`：查询与页面投影。

### `service`

`PersonalDatabaseService` 负责数据库打开、旧附件懒迁移、入库、提取、分页、排序、筛选、未解析提示以及公共库/全量观察者同步，是服务层总入口。

### `menu`

`PersonalDatabaseMenu` 负责：

- 复制原版背包布局。
- 维护 2x2 crafting、盔甲、副手和主背包槽位。
- 维护当前作用域以及个人库/公共库各自的查询状态。
- 维护玩家当前加强项配置。
- 将数据库交互转换为服务层操作。
- 在服务端生成数据库页面快照并同步给客户端。

### `client`

`PersonalDatabaseScreen` 负责全屏界面表现：

- 左侧使用 `VanillaPlayerInventoryPaneProvider` 复用原版背包背景和洋娃娃渲染，并固定停靠在页面左列。
- 右侧使用原版风格面板承载数据库网格与统计区，网格从左上角起排布并按分辨率自适应容量。
- 当 `Accessories` 饰品抽屉展开并遮挡数据库区域时，分页容量会按当前仍可见的数据库格重新计算，避免被遮挡格“吞掉”页面条目。
- 顶部提供个人库/公共库切换按钮、带物品图标的分类页签、带搜索图标的搜索框、高级搜索按钮、加强项按钮、排序下拉、分页控件和一键入库按钮。
- 排序下拉当前支持最近变更、最近新增、名称、数量、模组命名空间和物品 ID，多数规则都会在主排序键相同后继续用稳定键兜底，避免刷新后顺序抖动。
- 高级搜索使用折叠面板呈现，支持 `显示名称 / 物品 ID / 拼音 / 模组命名空间 / 数量加权` 五个要素同时启用，并分别配置 `低 / 中 / 高 / 关闭` 权重。
- 加强项使用独立折叠面板呈现，当前支持“拾取物品直入个人库”开关。

### `network`

自定义 payload 用于客户端与服务端同步：

- `DatabaseSnapshotPayload`：服务端下发页面快照，以及个人库/公共库各自的已记忆查询和当前加强项配置。
- `DatabaseQueryPayload`：客户端提交库切换、分类、排序、搜索、高级搜索配置和分页查询。
- `DatabaseEnhancementPayload`：客户端提交加强项配置变更。
- `DatabaseClickPayload`：数据库格子点击、Shift 快速提取以及拖拽物品入库。
- `DepositAllPayload`：当前所选库的一键入库。

### `command`

`/infiniteinventory database ...` 提供运维入口，用于：

- 立即创建完整数据库快照。
- 列出现有备份。
- 从指定快照恢复统一数据库，并在恢复前自动生成保护备份。

## 持久化与安全语义

数据库真实内容现在统一保存到 overworld `SavedData` 中，因此一个存档只有一份统一数据库文件，但其中同时承载：

- 一份公共库。
- 多份按玩家 UUID 分片的个人库。
- 旧个人附件迁移状态。

为了保证更新安全，数据库序列化固定带 `schema_version`，并遵循以下规则：

- 旧公共库 `SavedData` 会在加载时自动迁入统一结构。
- 旧个人库附件会在玩家首次打开数据库或首次访问个人库时懒迁移到统一存储。
- 迁移只会导入一次；如果统一存储里已存在该玩家个人库，则跳过旧附件导入并记录状态，避免重复叠加。
- 旧个人附件只会在迁移备份成功后清理；如果备份失败，旧附件会保留，避免破坏性清理。
- 旧版本没有 `first_added` 的条目会在加载时自动回填为 `last_modified`，保证升级后“最近新增”排序稳定可预测。

为了保证依赖暂缺时不丢条目，数据库加载遵循以下规则：

- 能正常解析的物品进入常规条目表。
- 暂时无法解析的物品不会被丢弃，而是保存为 `UnresolvedStoredEntry`。
- 每次数据库重新加载时，都会再次尝试把未解析条目恢复成正常条目。
- 未解析条目不会参与正常分页和提取，但会向当前查看该库的玩家发出提示。

为了保证入口物品不影响真实数据：

- `LivingDropsEvent` 会移除数据库快捷物品的掉落。
- `PlayerEvent.Clone` 在死亡且未启用 `keepInventory` 时补回快捷物品。
- 开启加强项后，玩家正常拾取到的地面物品会直接进入个人数据库，不经过玩家物品栏，也不受当前界面作用域切换影响。

这样可以确保数据库内容和入口物品都符合“死亡不掉落”的预期，同时真实数据库、入口物品和视图偏好彼此解耦。

## 备份与恢复

统一数据库使用自动轮换快照保护：

- 检测到旧格式公共库或旧个人附件迁移时，会先为当前统一逻辑模型写入迁移备份。
- 运行期只要统一数据库处于 dirty 状态，就会按 15 分钟最小间隔生成轮换快照。
- 自动管理的备份最多保留最近 12 份。
- 手动备份与恢复前保护备份不会参与自动轮换上限。

备份文件位于存档根目录下：

- `data/infiniteinventory/backups/`

恢复时只覆盖统一数据库逻辑模型，不依赖旧个人附件仍然存在。

## 同步语义

- 个人库修改后，只刷新当前玩家自己的数据库页面。
- 玩家开启“拾取物品直入个人库”并成功接管地面拾取后，如果当前正在查看个人库，也只刷新该玩家自己的页面。
- 公共库修改后，会刷新所有当前正在查看公共库的玩家页面。
- 通过命令恢复数据库后，会刷新所有当前打开数据库界面的玩家页面。
- 刷新时只会重算各自当前查询，因此不同玩家可以用不同排序、搜索和分页查看同一份公共内容。

## 当前兼容策略

当前左侧界面完整支持原版背包区、盔甲、副手和洋娃娃，并在安装 `Accessories` 后自动插入饰品槽面板。

`Accessories` 兼容当前采用可选依赖模式：

- 未安装 `Accessories` 时，界面与交互保持原版背包布局。
- 安装 `Accessories` 后，数据库终端可装备到 `back` 槽，按 `B` 键可直接打开数据库。
- 手持数据库终端右键仍然优先打开数据库，不会被 `Accessories` 的“右键快速装备”覆盖。
- 数据库界面中的 `shift` 快捷移动会识别 `Accessories` 槽位；`一键入库` 仍只扫描主背包与快捷栏，不会收走已装备物品。
- 自动拾取直入库只接管地面 `ItemEntity` 的正常拾取路径，不会替代其他来源的物品获得逻辑。

## 已知边界

当前版本有意保持以下边界：

- 非空搜索时结果固定按综合相关度优先：先比较精确、前缀、包含、模糊命中层级，再比较加权文本分和数量加权分，最后才落到手动排序与稳定键兜底。
- 搜索索引统一基于服务端固定 `zh_cn` 名称构建，同时补充 `物品 ID`、`模组命名空间`、拼音全拼与首字母索引，以保证单机和联机的中文检索一致。
- 分类页签为固定枚举，不支持玩家自定义标签。
- 右侧数据库区目前是自定义渲染，不是传统容器槽位。
- 公共数据库当前不做权限、审计或锁控制，冲突以服务端先处理成功的结果为准。
- 快捷物品默认通过创造栏获取，并支持在安装 `Accessories` 时作为背部饰品随身装备；后续可以增加更多入口。

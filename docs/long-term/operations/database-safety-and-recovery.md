# 数据安全与恢复说明

## 目标

这份文档只描述数据库安全相关的运行语义，方便后续排查“丢档”“升级兼容”“恢复快照”问题。

## 单一事实来源

- 真实数据库内容统一保存在 overworld `SavedData`。
- 个人数据库按玩家 UUID 分片保存在同一份统一数据库内。
- 旧 `PlayerDatabaseAttachment` 只作为迁移源保留，不再承载真实物品数据。
- 视图偏好仍保留在玩家附件中，因为它不是核心资产。

## 更新兼容

- 统一数据库与单库结构都带 `schema_version`。
- 旧公共库格式会在加载统一数据库时自动迁入新结构。
- 旧个人库附件会在玩家首次打开数据库或首次访问个人库时懒迁移。
- 如果统一存储中已存在该玩家个人库，则不会重复导入旧附件，避免数据翻倍。
- 数据库合并时会优先保留更具体的页签归属，并按条目中最大的最近修改序号推进后续序列，避免迁移、恢复或补写后“最近变更”排序失真。
- 从旧版本升级时，如果条目还没有 `first_added`，会自动用 `last_modified` 回填，保证“最近新增”排序在升级后不随机漂移。

## 未解析条目

- 当某个物品因模组缺失、注册名失效或组件暂不可解析而无法恢复为 `ItemStack` 时，条目不会被删除。
- 条目会进入 `UnresolvedStoredEntry` 列表，保存原始物品 NBT、数量、页签 ID、首次入库序号和最近修改序号。
- 这些条目暂时不参与普通 UI 展示与提取。
- 相关依赖恢复后，数据库下一次加载会自动重试解析并恢复条目。

## 备份目录

备份位于：

- `data/infiniteinventory/backups/`

文件名包含：

- UTC 时间戳
- 备份类型
- 备份原因

当前备份类型：

- `migration`
- `rolling`
- `pre_restore`
- `manual`

## 自动备份策略

- 旧格式公共库迁入统一存储前，会先生成迁移备份。
- 旧个人附件导入统一存储后、清理旧附件前，会先生成迁移备份。
- 数据库处于 dirty 状态时，会按 15 分钟最小间隔生成轮换备份。
- 自动管理的备份仅保留最近 12 份。

## 运维命令

- `/infiniteinventory database backup now`
- `/infiniteinventory database backup list`
- `/infiniteinventory database restore <snapshot>`

恢复命令执行前，会自动生成一份 `pre_restore` 保护备份。

## 排障建议

- 如果玩家报告数据库里某些物品“消失”，先确认是否只是进入未解析条目状态。
- 如果玩家报告“最近新增”排序异常，先确认是否刚经历旧版本升级；旧条目在首次升级后会统一把首次入库序号回填为旧的最近修改序号。
- 如果升级后数据库内容异常，先执行 `backup list`，确认迁移备份是否存在。
- 如果需要回滚，优先使用 `restore` 恢复最近的迁移备份或恢复前保护备份。
- 如果统一存储中已有个人库而旧附件仍非空，系统会跳过重复导入并记录迁移状态；这通常意味着此前已有一次成功或半成功迁移，需要优先检查备份和日志。
